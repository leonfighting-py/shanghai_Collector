### T4 定时发送真的发出来了

**怎么做**：

1. 云开发 → 数据库 → `reminders`，找一条 `sent: false` 的记录。
2. 把它的 `remind_at` 改成**过去的时间**，格式必须带 `+08:00`，例如：
   `2026-11-28T22:00:00+08:00`
3. 等下一个 **:05**（触发器每小时第 5 分跑一次，整点后 5 分钟）。

**应该看到**：手机微信收到「活动就要开始了，别错过」。

**没收到**：云开发 → 云函数 → `remind-sender` → 日志，找 `[remind-sender]` 那行，
会打印 `{"checked":1,"sent":1,...}`。按数字对号：

| 日志里看到的 | 含义 | 怎么办 |
|---|---|---|
| `checked: 0` | 没取到记录 | `remind_at` 格式不对（缺 `+08:00`）或 `sent` 已是 true |
| `skipped` 增加 | 被判为活动已结束/已下线 | 换一条记录；或 slug 对不上（`skip_reason` 里有原因） |
| `failed` 增加 | 发送接口报错 | 看日志里的 `errCode`；`43101` 是用户拒收，`45009` 是额度 |
| 日志里没有 `[remind-sender]` | 函数没跑 | 触发器没创建成功，回 T1 |

## 附录：几个容易误判的现象

| 现象 | 是不是 bug |
|---|---|
| 选「明天开始」的活动，显示「这场活动已经开始，不再提醒」 | 不是。提醒只在前一天 10:00 发，已过就不再排 |
| 拒绝授权后仍然收藏成功 | 不是。提醒是附加功能，不阻断收藏 |
| `reminders` 里有几条 `key` 是长串、`sent: true` 的老记录 | 不是。那是改键之前验证时产生的，会被判「活动已下线」跳过 |
| 定时任务跑完，`sent` 变成 true 但没收到消息 | 大概率是用户拒收（`43101`），看日志里的 `error` 字段 |

# 活动字段补齐方案：区域、价格、适合人群

日期：2026-10-12
状态：待实现
范围：只做采集侧的字段补齐和接口输出，不含首页、地图、小程序的界面改动。

## 1. 目标

给每条活动补上三类字段，供后续的场景标签、一句话找活动和地图使用：

- **区域**：上海 16 个区之一。
- **价格**：最低价、最高价、是否免费。
- **适合人群**：少量固定标签。

同时修掉场馆只写"上海"两个字的问题，因为区域要靠场馆推。

原则：**抓不到就留空，不猜。** 空值表示"不知道"，不表示"免费"或"适合所有人"。

## 2. 现状（2026-10-12 线上库，发布窗口内 119 条）

| 项 | 数字 |
|---|---|
| 场馆只写"上海" | 39 条（33%） |
| 场馆名里带区名 | 10 条 |
| 标题或摘要提到价格 | 1 条 |
| 标题或摘要提到免费 | 2 条 |
| 标题或摘要提到亲子、儿童类词 | 6 条 |
| 不同场馆名 | 66 个 |

`events` 表没有区域、价格、人群字段，`raw_events.raw_payload` 里也没有带。所有活动的 `source_url` 和 `signup_url` 相同，都指向详情页。

场馆只写"上海"的 39 条按信源分布：

| 信源 | 窗口内条数 | 只写"上海" |
|---|---|---|
| 格瓦拉 | 40 | 10 |

## 3. 字段设计

在 `events` 表加列，沿用 [repository.js:126](../../src/lib/repository.js:126) 的 `alter table ... add column if not exists` 写法：

| 列 | 类型 | 说明 |
|---|---|---|
| `district` | text，可空 | 16 个区名之一，统一写全称，如"浦东新区""黄浦区" |
| `address` | text，可空 | 详情页抓到的街道地址，原样保存 |
| `price_min` | numeric，可空 | 最低票价，单位元 |
| `price_max` | numeric，可空 | 最高票价，单一票价时与 `price_min` 相同 |
| `is_free` | boolean，可空 | `true` 免费，`false` 收费，空表示不知道 |
| `audience` | jsonb，默认 `[]` | 人群标签数组，取值见下 |
| `facet_provenance` | jsonb，默认 `{}` | 每个字段的来源，如 `{"district":"venue_dict","price":"detail"}` |

人群标签只用四个，空数组表示没有明确指向：

- `亲子`：明确面向儿童或家庭。
- `学生`：高校讲座、校内活动。
- `行业人士`：行业展会、专业会议、技术聚会。
- `英语友好`：英文信源，或页面写明英语进行。

`facet_provenance` 的取值：`parser`、`detail`、`venue_dict`、`rule`、`llm`。

## 4. 补齐流程

新增一个阶段，放在 [collect-job.js](../../src/lib/collect-job.js) 里分类过滤之后、分类下跌保护之前。此时活动数量已经过滤过，抓详情页的量最小。

四层依次执行，前一层填上的字段后一层不覆盖。

### 第 0 层：信源级修正

单场馆信源直接在信源配置里写死场馆，不走兜底：

- 上海新国际博览中心·展会 → 场馆"上海新国际博览中心"。
- 其他只对应一个场馆的信源同样处理，实现时逐个核对 `SOURCE_SEEDS`。

这一步零成本，先做。

### 第 1 层：详情页抓取

对每条活动抓 `signup_url`，按下面的顺序提取，取到即止：

1. **JSON-LD 的 Event 结构**：`location.name`、`location.address`、`offers.price` 或 `lowPrice` / `highPrice`、`isAccessibleForFree`、`audience`。
2. **页面正文的正则**：
   - 地址：匹配"上海市…区…路…号"或"地址："后面的内容。
   - 价格：匹配"¥80-680""票价：180/280/380 元""80 元起"等，取最小值和最大值。
   - 免费：匹配"免费入场""免费参观""无需门票""免票"。出现"免费"但同一句有"儿童免费""会员免费"等限定时，不算免费。
3. 场馆当前是"上海"且详情页拿到了具体场馆名时，回写 `venue`。

实现要求：

- 和现有的图片回填（[image-backfill.js](../../src/lib/image-backfill.js)）共用一次抓取。把"抓详情页"抽成一个带运行内缓存的函数，图片回填和本阶段都从它取，同一个地址一轮采集只请求一次。
- 加持久缓存表 `event_detail_cache`：主键 `source_url`，存提取结果和 `fetched_at`，有效期 7 天。发布是按窗口全量替换的（[repository.js:268](../../src/lib/repository.js:268)），不缓存的话每两天要把所有详情页重抓一遍。
- 并发 4，单个域名并发 2，沿用 `defaultFetchHtml` 的超时和重试，遵守 [robots.js](../../src/lib/robots.js) 的现有判断。
- 单条失败静默跳过并计数，不影响发布。

### 第 2 层：场馆字典与规则互补

新建 `src/lib/venue-profiles.js`，内容是一张场馆表：

```js
{ name: "上海博物馆东馆", aliases: ["上博东馆"], district: "浦东新区" }
```

- 首批覆盖窗口内出现的 66 个场馆名，由实现方起草，交给用户人工核对后再合入。
- 匹配方式：先做文本归一化，再按别名做子串匹配，**长别名优先**。例如"上海博物馆东馆三楼中国古代陶瓷馆尾厅"要命中"上海博物馆东馆"（浦东新区），不能命中"上海博物馆"（黄浦区）。
- 场馆名是场次或展览名而不是场馆的（如"CHIIKAWA DAYS 特展- 中国内地首展""沉浸式金鱼剧场艺术展"），字典不收，留给详情页地址解决。

互补规则：

| 已知 | 推出 | 来源标记 |
|---|---|---|
| 场馆命中字典 | 区域 | `venue_dict` |
| 场馆名或地址里含"XX区" | 区域 | `rule` |
| 地址有、场馆是"上海" | 用地址去字典里反查场馆名；查不到就把场馆改成地址 | `rule` |
| 分类是"高校讲座" | 人群加 `学生` | `rule` |
| 标题、摘要或详情正文含"亲子""儿童剧""适合 X 岁""少儿" | 人群加 `亲子` | `rule` |
| 信源是行业展会或技术社区（新国际博览中心、GDG、SegmentFault、钛媒体） | 人群加 `行业人士` | `rule` |
| 信源是英文站（SmartShanghai） | 人群加 `英语友好` | `rule` |

**价格不做任何推断。** 不能因为场馆是博物馆就标免费，特展通常另收费。

### 第 3 层：LLM 兜底

前三层之后仍然缺字段、并且详情页正文抓到了的活动，批量交给模型。复用 [siliconflow.js](../../src/lib/siliconflow.js) 的调用和预算熔断，写法参照 [event-enrichment.js](../../src/lib/event-enrichment.js)。

- 输入：标题、场馆、分类、详情页正文的前 1500 字。
- 输出：`{district, address, price_min, price_max, is_free, audience}`，每项都允许 `null`。
- 提示词要求：正文没写的一律返回 `null`，不得推测。
- 结果校验，不通过的字段丢弃：
  - `district` 必须在 16 区名单里。
  - `audience` 的每一项必须在四个标签里。
  - 价格数字必须能在输入正文里原样找到。
  - `is_free` 为 `true` 时，正文里必须有"免费""免票"或同义词。
- 独立开关 `LLM_FACETS_ENABLED`，默认关。不要并进现有的标题摘要提示词，避免影响已经稳定的输出。

### 抓不到的

四层都没有结果的字段保持空值，`facet_provenance` 里不写这个键。后续界面按"未知"处理：筛"免费"只出 `is_free = true` 的活动。

## 6. 实现顺序

1. **探测（先做，决定后面值不值得做）**：写 `scripts/facets-probe.js`，每个信源取 5 个详情页，报告 JSON-LD、地址、价格、免费字样各能提取到多少。格瓦拉、豆瓣、票牛的详情页是否由脚本渲染、正文里有没有票价，目前没有验证过。如果主要票务源的详情页拿不到价格，价格这一项要换接口抓或者放弃，先向用户汇报再继续。
2. 加列、读写、合并、接口输出，带测试。
3. 第 0 层信源修正。
4. 详情页共用抓取和缓存表，第 1 层提取。
5. 场馆字典和第 2 层规则。字典交用户核对。
6. 第 3 层 LLM 兜底，默认关。
7. 覆盖率脚本 `scripts/facets-coverage.mjs`，输出第 2 节那张表的新数字，外加各字段覆盖率和各层贡献。

## 7. 测试

沿用 `node --test`，不发真实网络请求，抓取函数和模型调用都用注入的假实现（现有测试的做法）。

- 提取函数：每种价格写法、地址写法、免费字样和带限定的"免费"各一个用例，样本放 `test/fixtures`。
- 场馆字典：长别名优先的用例；场次名不命中的用例。
- 互补规则：表里每一行一个用例。
- LLM 校验：编造的价格、名单外的区、名单外的标签都被丢弃。
- 合并：两个信源一方有值一方为空；两方都有值。
- 缓存：有效期内不重抓，过期重抓。
- 仓库层：新字段写入和读出一致。

## 8. 验收

跑一轮完整采集后，用覆盖率脚本对比第 2 节的基线：

| 指标 | 基线 | 目标 |
|---|---|---|
| 场馆只写"上海" | 33% | 10% 以下 |
| 有区域 | 约 8% | 80% 以上 |
| 演出音乐类价格已知（有票价或已知免费） | 约 0% | 50% 以上 |
| 有人群标签 | 约 5% | 不设目标，如实报告 |

目标值是估计，没有实测依据，以第 1 步探测的结果为准，探测后可以调整。

准确性另外抽查：随机 30 条，人工对照详情页，区域和价格的错误不超过 2 条。超过时先关掉出错最多的那一层再查原因。

## 9. 顺带发现，不在本次范围

- 意大利文化处的信源里有苏州的展览（"黄金：中西交流中的贵金属展"，地址在苏州吴文化博物馆），被兜底成"上海"发布了。详情页地址抓到以后，可以用它识别外地活动，是否自动剔除另行决定。
- 地图需要的经纬度没有包含在本方案里。场馆字典里可以预留 `lat` / `lng` 两个可空字段，填值需要地理编码服务，另起方案。
- 供给偏科：演出音乐和展览占 88%，线下活动 9 条、高校讲座 4 条。字段补齐以后，"带娃""免费"这类场景能筛出的活动仍然不多，要靠加信源解决。

# 公众号信源：有没有「长期可用」的采集能力

日期：2026-11-20
背景：第 11 天加线下活动信源时发现，区图书馆、社区文化中心、市集主办方基本只在微信公众号发活动，
官网没有可解析列表。要覆盖这类供给，绕不开公众号。本文回答一个问题：
**公众号能不能长期稳定地采，用什么方式。**

## 1. 结论

1. **官方没有提供获取他人公众号文章列表的接口**，也没有「授权后再读」的路子。这条路彻底不通。
2. **所有自建方案都在和微信风控对抗**，没有一劳永逸的。差别只是「多久需要人工介入一次」。
3. **按本项目的量级（20~30 个号、每天 1~2 轮），微信读书接口方案够用**——
   社区反馈的「必须上号池」是 350~3000 个号的场景，我们差两个数量级。
4. 如果不想承担任何风控运维，**买第三方合规 API 是最省事的**：单页 $0.02 量级，
   30 个号每天 1 页 = 每天不到 1 元。它把风控成本转成了钱。

## 2. 官方能力：确认不可用

| 接口 | 能拿到什么 | 对本项目 |
|---|---|---|
| `/cgi-bin/freepublish/batchget` | 只能拿**未开启群发通知**的发布内容 | 无用，公众号正常推送都带通知 |
| `/cgi-bin/freepublish/getarticle` | 只对**已认证**的号开放，且是**自己的号** | 无用 |
| 数据统计接口 | 自己号的数据 | 无用 |

微信开放社区官方答复（2026）：「有没有可以获取所有公众号已发布文章的接口？**没有**」。
另：2025 年 7 月起，个人主体、未认证主体的发布类接口权限被回收。

## 3. 四类自建方案

来源：`rachelos/we-mp-rss` issue #442 的社区总结（2026-08），交叉验证 Wechat2RSS discussion #356。

| 方案 | 技术手段 | 速度 | 风控 | 维护成本 | 现状 |
|---|---|---|---|---|---|
| ① 公众号后台超链接接口 | 自己申请一个公众号，登录后台用「超链接」功能换任意号的文章列表 | 300 号单日列表 20 分钟 | 需要每 2~3 天重新扫码 | 中 | **2026-07-30 官方已封** |
| ② 微信读书接口 | `weread.qq.com/web/mp/articles?bookId=&offset=`，需登录 Cookie | 300 号单日列表 **6 小时+** | 严格，「小黑屋」24h 解封，长期要 2~3 个号轮换 | 中 | 可用（wechat-mp-tools 仍在维护） |
| ③ PC 微信动态凭据 | 本机常驻登录的 PC 微信，访问文章生成凭据 | 快 | 凭据几小时过期 | 高（要一台常驻 Windows + 微信） | 可用 |
| ④ 手机端注入 + 中间人 | 局域网手机代理拦截，注入脚本翻页 | 慢 | 模拟真人，较难封 | 高（两台设备） | 只适合单次 |

代表项目：① we-mp-rss、wechat-article-exporter（已停维护）；② x554960766/wechat-mp-tools、
cooderl/wewe-rss（已停维护）、ttttmr/Wechat2RSS（闭源）；③ yeximm/Access_wechat_article、
kanadeblisst00/pywxrobot4、WCPlus；④ lqqyt2423/wechat_spider。

### 稳定性证据（不是听说，是用户实测）

- Wechat2RSS discussion #356（2026-02）：部署后抓取从「1 天内」退化到「3~4 天」，
  用户自查「被风控了，微信读书手动解封后半小时又被风控，如此反复」；作者回复「任务积压太多，过段时间就好」。
- 同一 issue 里有人转述 wechat2rss「私有实例 14 个月零中断」——同篇文章是推广性质，可信度低于上面的实测。

## 5. 对本项目的建议

**量级判断**：本站要跟的上海活动类公众号，估计 20~30 个（区图书馆、区文化馆、美术馆、市集主办方）。
每天抓 1 次、每个号取第 1 页（20 条）就够——一天 30 次请求。

**推荐顺序**：

1. **先试微信读书方案（②）**，单账号、严格限频（每天 1 轮、每号间隔 3~5 秒）。
   按社区数据，我们的量级远低于风控阈值。代价：Cookie 会过期，需要偶尔（周级）重扫码。
2. Cookie 过期要人肉处理这件事，**必须配告警**：连续 2 轮抓取 0 条就推飞书（现成的 `alerting.js` 通路）。
3. 如果人工重扫的频率让人受不了（比如一周两次），**换商业 API**。
   DataXAPI 单价 $0.02/页，30 号 × 每天 1 页 ≈ $0.6/月，比自己维护的风险便宜。
4. ①②③④ 全部有「账号被限制」的风险，**不要用主账号**，用一张专门的小号。

**不建议**：直接写爬虫抓 `mp.weixin.qq.com` 文章页。文章页能打开，但没有列表入口，
必须靠搜索或转发链接进，做不成「按号跟更」。

## 6. 合规提示

- 采集的是公开发布的公众号文章，不含用户数据；但仍受《网络安全法》《数据安全法》约束，
  需控制频率（不对目标服务器造成压力）、保留来源标注。
- 商业 API 的合规责任在服务方，但要在合同/条款里确认其数据来源合法性。
- 转载正文到站内属于另一件事，本项目只取「标题 + 时间 + 地点」，不搬运全文。

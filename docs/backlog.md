## 1. 只有地址的活动补地理编码

**记录时间**：2026-11-25。用户明确要求「等这次方案全部出完之后再做」。

**现状**（窗口 249 场）：

| | 条数 | 说明 |
|---|---|---|
| 有坐标、能上文地图 | 112（45%） | 48 个场馆，靠 `venue-profiles.js` 匹配到字典，再从 `venue-coordinates.js` 取坐标 |
| 只有地址、没有坐标 | 137（55%） | 场馆名是「大场镇社会事业发展服」「岚皋西路306弄7号」「中原路188号」这类，字典里没有 |

**为什么字典补不动**：这些是街道/社区级活动，场馆名本身就是个门牌号，逐个补进字典等于把地址表抄一遍，而且每轮采集都会出现新的。

**做法**：

1. 对「没匹配上字典、但有 `address`」的活动调地理编码；
2. **按规范化地址缓存**（`上海市徐汇区长乐路989号` 与 `长乐路989号` 要归一到同一个键），避免每轮重复调用；
3. 坐标落库（`events.address_coord` 或单独的 `address_coordinates` 表，按地址键存）；
4. 前端用**更浅的圆点**区分「确切场馆」与「只到地址」，不要混成一种。

**成本估算**：去重后约 60–100 个新地址/轮，高德 Web 服务 QPS 3 → 30 秒左右，可放在发布后异步跑。

**已知风险**：
- 地址字符串脏，归一化规则要实测（去「上海市」「号」、统一「弄/支弄」写法）；
- 部分地址是主办方办公地址而不是活动场地（第 11 天那个苏州案例就是），地理编码会把它当上海画上去 —— 需要配合外地守门一起看。
